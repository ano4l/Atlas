# Atlas mobile

Atlas is a React Native + Expo application targeting iOS and Android only. The consumer app has no browser target. The native map uses Apple Maps on iOS and Google Maps on Android, with an illustrative indoor corridor network.

## Run

From the repository root:

- Install: `corepack pnpm install --frozen-lockfile`
- Open in Expo Go: `corepack pnpm --filter mobile start`
- Compile and launch Android: `corepack pnpm --filter mobile android`
- Compile and launch iOS on a Mac: `corepack pnpm --filter mobile ios`
- Validate types: `corepack pnpm --filter mobile typecheck`
- Validate demo routing: `corepack pnpm --filter mobile test`

The root .npmrc enables hoisted dependencies for Expo SDK 51 native prebuild and autolinking. Safe-area handling uses react-native-safe-area-context. The app fills the device.

For a standalone Android build, copy .env.example to the ignored .env and supply an Android-restricted Google Maps key, or set GOOGLE_MAPS_API_KEY in the EAS build environment. app.config.ts passes it into the native configuration. Expo Go provides its own map-provider setup.

## iOS compilation

The ios-simulator profile in eas.json builds a Release simulator app on EAS's macOS builders without Apple signing credentials:

`eas build --platform ios --profile ios-simulator`

Run that command from apps/mobile. The simulator artifact requires a Mac to launch. Native compilation of the completed UI was verified on 2026-10-12 in [final EAS build 1aaa674b](https://expo.dev/accounts/certi4no/projects/indoor-navigation-mobile/builds/1aaa674b-3c49-4681-9475-8dd21ca3e6ef). Runtime verification limits and previous builds are recorded in BUILD_CHECKS.md.

Native directories are generated by Expo and ignored in Git. Normal iOS prebuild requires macOS or Linux; Expo SDK 51's CLI skips iOS on Windows. A JavaScript export is a bundle check, not proof of successful native compilation or device execution.

## Maps and flows

Routes are calculated locally through the fixture's connected corridor network and end at the selected destination. Step-free routing uses lifts. Search and Explore share category filters and directory rows; previews, explicit demo steps and arrival share the same selected route.

Indoor geometry, distances, place metadata and position are illustrative data. They are not a surveyed Sandton City floor plan, live positioning or backend routing. Preferences apply to the current session. There are no simulated voice, download, permission-grant or diagnostics controls.

## Xcross verification

The installed Windows executable is at %LOCALAPPDATA%\\xcross\\bin\\xcross.exe, version 2.0.2. It was actually tested against this project on 2026-10-12:

- `xcross react-native --help`: command not found.
- `xcross flutter build --no-pub`: after a native iOS project was generated for the probe, failed with `pubspec.yaml not found`.
- `xcross compose build --configuration debug`: failed with `No settings.gradle.kts found`.

No successful Xcross compilation is claimed. Another React Native project's working Xcross command or wrapper is needed to reproduce that workflow. EAS compilation is independent evidence and does not count as a successful Xcross build.
